\section{Waveform Feature Computation and Selection}
\label{sec:ch3-waveform-features}

The arc-detection firmware computes waveform features from current samples
rather than from RMS current alone. This is necessary because a series arc can
leave the load current below a conventional breaker trip level while still
introducing low-current gaps, restrike pulses, irregular zero-crossing
behavior, and mid/high-frequency energy [34], [35], [53], [54]. The firmware
uses a 512-sample frame at a 27kHz target sampling rate, with a 256-sample
hop. A Hann window is applied before the FFT to reduce spectral leakage, which
is standard practice in discrete Fourier analysis [70], [75].
For consistency with the feature grouping used in
Chapter~\ref{chap:review-of-related-literature},
the computed features are interpreted as either waveform-disturbance
indicators or conduction-intermittence indicators. Waveform-disturbance
features describe spectral, harmonic, residual, and cycle-shape changes, while
conduction-intermittence features describe low-current dwell, interruption,
and restrike-related behavior.
The equation subsections below are implementation-level groups used to keep
related computations together. Current-magnitude and conduction-gap features
primarily support the conduction-intermittence family, while spectral,
residual, waveform-shape, and harmonic features primarily support the
waveform-disturbance family. Some features, such as RMS-current departure,
can support both interpretations depending on whether the change is caused by
load transition or arc-related interruption.

\subsection{Feature-Set Contract Between Firmware, Trainer, and PWA}
\label{sec:ch3-feature-contract}

The firmware, trainer, exported model headers, and PWA do not use one single
feature list for every purpose. In the inspected firmware revision, the runtime
feature-layout header defines 20 waveform-related fields for export and
logging. The deployed Random Forest arc model uses only six of those waveform
features, then appends six context one-hot fields and one context confidence
value for a 13-input model vector. The current live PWA dashboard renders only
10 waveform-feature cards, while the PWA metadata and session viewer retain a
broader 14-feature order for review and CSV inspection.

Table~\ref{tab:ch3-feature-contract} gives the source-of-truth contract used
in this paper. A ``Yes'' in the arc-model column means that the feature is
one of the six waveform inputs in the deployed Random Forest header. Context
features used by the load-context model are noted separately because they
support the context fields later appended to the arc vector, but they are not

Table~\ref{tab:ch3-feature-contract} shows that the prototype does not compute only the 10 features shown
on the live dashboard. It exports 20 candidate waveform-related feature
fields, deploys six as base waveform inputs to the arc model, uses six
context-model features to produce the context fields, displays 10 live
feature cards in the current PWA dashboard, and keeps a broader metadata order
for session review. This is for flexibility in future model refinement and to 
support the interpretability and review of a wider range of features during 
testing and analysis. The next sections describe the physical meaning 
and firmware computation of these features.

\subsection{Collected Candidate Features}
\label{sec:ch3-collected-candidate-features}

The current RMS value used in the feature frame is computed as
\begin{equation}
  I_{\mathrm{rms}} =
  \sqrt{\frac{1}{N}\sum_{n=0}^{N-1} i[n]^2}.
  \label{eq:feature-rms}
\end{equation}
In (\ref{eq:feature-rms}), $i[n]$ is the calibrated current sample after the
firmware's current conversion path and $N$ is the number of samples in the
frame. RMS current is not counted as one of the 20 exported feature IDs, but
it is the physical reference used by overload logic and by several arc
features.

\subsubsection{Current-Magnitude and Baseline Features}
\label{sec:ch3-current-baseline-features}

The RMS-current baseline z-score is
\begin{equation}
  Z_I =
  \frac{|I_{\mathrm{rms}}-\mu_I|}{\sigma_I+10^{-6}} .
  \label{eq:feature-irms-zscore}
\end{equation}
In (\ref{eq:feature-irms-zscore}), $\mu_I$ and $\sigma_I$ are the adaptive
baseline mean and standard deviation maintained by the firmware. The feature
\feature{abs_irms_zscore_vs_baseline} is dimensionless, clipped by firmware,
used by the deployed arc model, and shown in the PWA. It helps detect current
magnitude departures that can accompany interruption and restrike.

The absolute RMS-current step is
\begin{equation}
  \Delta I_{\mathrm{rms}} =
  |I_{\mathrm{rms}}[k]-I_{\mathrm{rms}}[k-1]|.
  \label{eq:feature-delta-irms}
\end{equation}
The feature \feature{delta_irms_abs} is expressed in amperes, supports the
context model, and is shown in the PWA. It helps distinguish load turn-on,
load-family changes, and abrupt waveform events from steady operation.

The voltage-sag feature is computed from the healthy voltage baseline:
\begin{equation}
  V_{\mathrm{sag}} =
  100\max\left(0,\frac{B_V-V_{\mathrm{rms}}}{B_V}\right).
  \label{eq:feature-v-sag}
\end{equation}
In (\ref{eq:feature-v-sag}), $B_V$ is the voltage baseline and
$V_{\mathrm{rms}}$ is the calibrated RMS voltage. The firmware logs
\feature{v_sag_pct} for event interpretation, but the deployed arc model does
not use it as a base feature.

\subsubsection{Conduction-Gap and Pulse Features}
\label{sec:ch3-gap-pulse-features}

The low-current ratio measures the portion of the frame close to zero current:
\begin{equation}
  L_{\mathrm{ratio}} =
  \frac{100}{N}\sum_{n=0}^{N-1}
  \mathbf{1}
  \left(
  |i_c[n]| \leq
  \max(0.035,\,0.06\max(I_{\mathrm{rms}},0.10))
  \right).
  \label{eq:feature-low-current-ratio}
\end{equation}
In (\ref{eq:feature-low-current-ratio}), $i_c[n]$ is the cleaned current
sample and $\mathbf{1}(\cdot)$ is an indicator function. The result is a
percentage. The feature \feature{low_current_ratio} is used by the deployed
arc model and shown in the PWA because a high value can indicate current
interruption during a series arc.

The maximum low-current run is computed as
\begin{equation}
  t_{\mathrm{low,max}} =
  \frac{1000\,N_{\mathrm{run,max}}}{f_s}.
  \label{eq:feature-low-current-run}
\end{equation}
In (\ref{eq:feature-low-current-run}), $N_{\mathrm{run,max}}$ is the longest
consecutive low-current run and $f_s$ is the sampling rate. The output is in
milliseconds. The feature \feature{max_low_current_run_ms} is used by the
deployed arc model and shown in the PWA because series arcs can create
observable extinction gaps.

The zero-dwell ratio measures near-zero dwelling around zero crossings. The
firmware uses zero-crossing windows when crossings are stable and falls back
to the low-current ratio when a robust dwell estimate is unavailable:
\begin{equation}
  D_0 =
  100\frac{N_{\mathrm{near\ zero}}}{N_{\mathrm{zc\ window}}}.
  \label{eq:feature-zero-dwell}
\end{equation}
The feature \feature{zero_dwell_ratio} is a deployed arc-model input and is
logged to CSV. In the current live PWA, the card label may appear as
zero-cross variance or ZCV, but the quantity discussed in this paper is the
zero-dwell or near-zero conduction behavior used by the arc model.

The residual pulse count per cycle is
\begin{equation}
  P_{\mathrm{cycle}} =
  \frac{N_{\mathrm{pulses}}}{N/f_{\mathrm{s}}\cdot f_0}.
  \label{eq:feature-pulse-count}
\end{equation}
In (\ref{eq:feature-pulse-count}), $N_{\mathrm{pulses}}$ is the detected
residual-pulse count, $f_s$ is the sampling rate, and $f_0$ is the mains
frequency. The feature \feature{pulse_count_per_cycle} is retained in the PWA
session metadata and logged because short residual pulses are physically
consistent with arc restrike, although the deployed arc model does not use
this feature directly.

\subsubsection{Spectral and Residual Features}
\label{sec:ch3-spectral-residual-features}

The mid/high-frequency spectral flux feature compares the normalized magnitude
spectrum of the present frame with the previous frame:
\begin{equation}
  F_{\mathrm{midhf}} =
  50\sum_{k=k_0}^{k_1}
  \left|
  \frac{M_k}{\sum_{r=k_0}^{k_1}M_r}
  -
  \frac{M_{k,\mathrm{prev}}}{\sum_{r=k_0}^{k_1}M_{r,\mathrm{prev}}}
  \right|.
  \label{eq:feature-spectral-flux}
\end{equation}
In (\ref{eq:feature-spectral-flux}), $M_k$ is the FFT magnitude in the
900Hz to 9000Hz flux band after skipping bins around mains harmonics. The
feature \feature{spectral_flux_midhf} is dimensionless, used by both the
context model and deployed arc model, and shown in the PWA.

The high-frequency energy delta compares the high-frequency energy share with
its baseline:
\begin{equation}
  \Delta E_{\mathrm{HF}} =
  10\log_{10}
  \left(
  \frac{E_{\mathrm{HF}}/(E_{\mathrm{HF}}+E_{\mathrm{UM}})+\epsilon}
       {B_{\mathrm{HF}}+\epsilon}
  \right).
  \label{eq:feature-hf-delta}
\end{equation}
In (\ref{eq:feature-hf-delta}), $E_{\mathrm{HF}}$ is the 4500--9000Hz band
energy, $E_{\mathrm{UM}}$ is the 900--4500Hz upper-midband energy,
$B_{\mathrm{HF}}$ is the baseline high-frequency share, and $\epsilon$ is a
small numerical offset. The result is in decibels, supports the context model,
and is shown in the PWA as \feature{hf_energy_delta}. The separate
\feature{delta_hf_energy} is the frame-to-frame absolute change of this
high-frequency measure and is logged for analysis.

The midband residual ratio is computed from FFT energy in the 220--3200Hz
midband after excluding harmonic bins:
\begin{equation}
  R_{\mathrm{mid}} =
  20\log_{10}
  \left(
  \frac{\sqrt{E_{\mathrm{mid,res}}}/N}
       {\max(B_I,\,0.10)}
  \right).
  \label{eq:feature-midband-ratio}
\end{equation}
In (\ref{eq:feature-midband-ratio}), $E_{\mathrm{mid,res}}$ is the residual
midband energy, $N$ is the frame length, and $B_I$ is the baseline RMS
current. The output is in decibels and is used by both the context model and
the deployed arc model.

The residual crest factor is
\begin{equation}
  C_{\mathrm{res}} =
  20\log_{10}
  \left(
  \frac{\max_n |r[n]|}{\sqrt{\frac{1}{N}\sum_{n=0}^{N-1}r[n]^2}}
  \right),
  \label{eq:feature-residual-crest}
\end{equation}
where $r[n]$ is the residual waveform after low-frequency content is removed.
The feature \feature{residual_crest_factor} is retained in the PWA session
metadata and logged to describe spike-like residual behavior.

The edge-spike ratio is
\begin{equation}
  S_{\mathrm{edge}} =
  20\log_{10}
  \left(
  \frac{A_{\mathrm{edge}}}{\max(B_I,\,0.10)}
  \right),
  \label{eq:feature-edge-spike}
\end{equation}
where $A_{\mathrm{edge}}$ is the firmware's edge-burst amplitude estimate.
The feature \feature{edge_spike_ratio} is retained in the PWA session metadata
and helps identify restrike-like edges, but it is not a deployed arc-model
base input.

The firmware also logs \feature{delta_flux}, the frame-to-frame change in
spectral flux, and \feature{suspicious_run_energy}, a leaky internal score
that increases when several arc-like cues occur together. These features
support logging and future refinement; they are not used directly by the
deployed Random Forest base vector.

\subsubsection{Waveform Shape and Harmonic Features}
\label{sec:ch3-shape-harmonic-features}

The firmware computes current THD from the fundamental and harmonic tone
powers:
\begin{equation}
  \mathrm{THD}_I =
  100\sqrt{\frac{\sum_{h=2}^{10}P_h}{P_1}} .
  \label{eq:feature-thd}
\end{equation}
In (\ref{eq:feature-thd}), $P_1$ is the tracked fundamental tone power and
$P_h$ is the tone power of harmonic $h$. The feature \feature{thd_i} is a
percentage, supports the context model, and is shown in the PWA.

The half-cycle asymmetry is
\begin{equation}
  A_{\mathrm{half}} =
  100\frac{|I_{\mathrm{pos}}-I_{\mathrm{neg}}|}
  {0.5(I_{\mathrm{pos}}+I_{\mathrm{neg}})}.
  \label{eq:feature-halfcycle-asymmetry}
\end{equation}
In (\ref{eq:feature-halfcycle-asymmetry}), $I_{\mathrm{pos}}$ and
$I_{\mathrm{neg}}$ are the positive and negative half-cycle RMS values. The
feature \feature{halfcycle_asymmetry} is dimensionless in percent, supports
the context model, and is shown in the PWA.

The peak-fluctuation coefficient of variation is
\begin{equation}
  C_{V,\mathrm{peak}} =
  100\frac{\sigma(A_{\mathrm{pk}})}{\mu(A_{\mathrm{pk}})} ,
  \label{eq:feature-peak-fluctuation}
\end{equation}
where $A_{\mathrm{pk}}$ is the set of cycle peak magnitudes in the frame. The
feature \feature{peak_fluct_cv} is retained in the PWA session metadata and
describes irregular cycle peaks.

The cycle normalized mean-squared error is represented as
\begin{equation}
  E_{\mathrm{cycle}} =
  100\,\mathrm{median}
  \left(
  \frac{\sum_m (c_j[m]-c_{j-1}[m])^2}
       {\sum_m c_{j-1}[m]^2+\epsilon}
  \right),
  \label{eq:feature-cycle-nmse}
\end{equation}
where $c_j[m]$ and $c_{j-1}[m]$ are adjacent cycle segments aligned by the
firmware. The feature \feature{cycle_nmse} is logged for waveform comparison
but is not a deployed arc-model base input.

\subsection{Selected Features Used by the Deployed Arc Model}
\label{sec:ch3-selected-arc-features}

The deployed arc model uses
\feature{max_low_current_run_ms}, \feature{zero_dwell_ratio},
\feature{low_current_ratio}, \feature{abs_irms_zscore_vs_baseline},
\feature{midband_residual_ratio}, and \feature{spectral_flux_midhf}. These
six waveform features cover conduction gaps, current-magnitude departure, and
mid/high-frequency disturbance. The model then appends six context-family
one-hot inputs and one context-confidence input. The context inputs improve
interpretation across appliance families, but they are not additional
waveform features.
